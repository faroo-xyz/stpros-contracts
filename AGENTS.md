# Repository rules for agents and contributors

These rules apply to every change in this repository. The architecture they
protect is the frozen R1-final + A1 design in the research repository
(`faroo-contracts-reserch/architecture-hardening/`); a change that deviates from
it needs a design amendment first.

## Secrets and isolation

- Never read, open, search or print `.env`, `.env.*`, keys or credentials.
- `hardhat.config.ts` imports `dotenv/config`, and **every Foundry binary
  (`forge`, `cast`, `anvil`, and Halmos through forge) loads `.env` from its
  working directory and every parent directory at startup, for every
  subcommand, including offline ones such as `cast keccak` or `forge --version`.**
  Never run them in this working tree.
- Run them only inside an export:

  ```sh
  dest=$(tools/verify/export.sh | tail -1)        # allowlisted, .env-free copy
  tools/verify/run.sh "$dest" forge test          # empty environment
  ```

  Python tools call Foundry binaries only through `common.run_foundry`
  (fresh temporary directory, empty environment).
- RPC endpoints are passed explicitly and are the public read-only ones
  (`tools/lib/rpc.py`): `https://rpc.pharos.xyz` (mainnet, chain 1672) and
  `https://atlantic.dplabs-internal.com` (testnet, chain 688689). Both reject
  `eth_getLogs` ranges above 1,000 blocks and rate-limit per IP.

## Chain safety

- No deployment, broadcast, upgrade or push is part of any development batch.
  Local forks (`anvil`, `vm.createSelectFork`) may impersonate accounts; nothing
  is ever sent to a public endpoint except read-only calls.
- `deployments/` is append-only. Never overwrite or delete a historical record.
  The deploy scripts pass `alwaysOverride: true`; a redeploy would overwrite the
  record of the previous implementation, so archive it first.

## Legacy fidelity

- Tests about deployed behaviour use the recorded bytecode in
  `test/fixtures/legacy/` (generated by `tools/release/fixtures.py` from
  `deployments/`, checked against on-chain code at the pinned blocks) through
  `test/helpers/LegacyTopology.sol` and the ABI-derived
  `test/helpers/LegacyInterfaces.sol`. Never substitute current `contracts/`
  sources for a historical implementation.
- The real WPROS pays native with a 2300-gas stipend. Use `test/mocks/WPROS9.sol`
  (differentially tested against both deployed WPROS runtimes), not
  `MockWPROS`, wherever the unwrap path matters.

## Baselines and gates

- Snapshots in `snapshots/` are regenerated only by their tools and checked
  with `--check` (`tools/verify/check_all.sh`). Never refresh a snapshot, lower a
  bound, drop a test or widen an assumption to obtain a pass; an intended change
  is committed together with the reason for it.
- Report unrun checks as NOT RUN and incomplete evidence as INCOMPLETE, never
  as PASS.

## Workflow

- Develop directly on `main`, as approved by the owner. Do not create development branches or merge the `dev` (tbPROS) branch.
- One reviewable batch per commit boundary, as listed in the implementation
  roadmap of the research repository.
